# AI 貼圖角色專案與 AI 文字排版規格

## 問題陳述

AI 貼圖生成工具目前每批只接受一張參考圖，且每張貼圖各自產生。使用者難以在同一組與不同批次中維持角色的臉部、髮型、服裝、比例與畫風。補做新貼圖時，也必須重新上傳圖片並重建設定，沒有可重用的角色基準。

目前貼圖文字可讓 AI 繪製，也可由工具後製疊字。後製疊字樣式固定、無法分段，且不符合使用者希望由 GPT 自行完成風格化中文文字與構圖的方向。

## 解決方案

AI 貼圖生成工具提供「單次貼圖」與「角色專案」兩種流程。

單次貼圖維持快速流程，可直接以一至五張參考圖產生一組貼圖，不建立可重用資料。第一張是主要參考圖，其餘可選擇標記為上方視角、下方視角、左側或右側。角色專案採兩階段流程：先上傳正面、上方視角、下方視角、左側與右側五張參考圖，產生並確認角色定稿圖，再以定稿圖與角色設定產生貼圖。「上方視角」指相機從角色上方往下拍，「下方視角」指相機從角色下方往上拍，不是角色上半身與下半身。

角色定稿圖必須是所選插畫風格下的單一角色、正面或微側全身、中性姿勢與表情、無文字、簡單純色背景，並清楚呈現臉部、髮型、身形、服裝與固定配件。使用者確認前不能開始產生貼圖；更換任一原始參考圖、固定角色特徵、固定配件或插畫風格後，既有確認立即失效，必須重新產生並確認。預設服裝屬於可變設定，變更時不會使角色身分定稿失效。

角色專案可下載為角色檔，日後匯入後不必重新上傳五張圖。角色檔保存角色定稿圖、原始角度參考圖、固定角色特徵、預設服裝、風格設定、供應商、模型 ID 與提示詞版本，但絕不保存 API key。後續批次預設只以角色定稿圖與角色設定產生；個別貼圖明顯失真時，可在「重生這張」啟用嚴格參考，自動附加角色檔中的五張原始角度參考圖。

預設引擎改為 OpenAI 的 `gpt-image-2`，Google 保留為手動選擇的替代供應商。文字只提供「讓 AI 畫文字」與「不產生文字」兩種模式。文字欄位支援最多兩個手動段落，AI 必須保留每段內容與順序，但依動作及構圖自行決定段落位於上下、左右、對話框或其他適合的位置。

## 使用者故事

1. 身為 AI 貼圖生成工具使用者，我想在單次貼圖與角色專案間選擇，讓我能依是否需要後續重用角色來選擇流程。
2. 身為單次貼圖使用者，我想從單一參考圖產生一組貼圖，讓既有快速流程得以保留。
3. 身為單次貼圖使用者，我想加入最多五張帶有角度標記的參考圖，讓一次性貼圖也能有較佳的角色一致性，而不必建立角色專案。
4. 身為角色專案使用者，我想上傳正面、上方、下方、左側與右側參考圖，讓產生引擎可從多個角度辨識角色。
5. 身為角色專案使用者，我想讓每個參考圖欄位標示所需角度，讓我不會誤上傳模糊或重複的視角。

7. 身為角色專案使用者，我想在產生貼圖組前先產生角色定稿圖，讓我能先確認角色身分、服裝、比例與畫風。

9. 身為角色專案使用者，我想讓已確認的角色定稿圖成為後續每張貼圖的預設參考，讓角色在同一批貼圖中保持可辨識性。
10. 身為角色專案使用者，我想在定稿後下載角色檔，讓我能在不重新上傳參考照片的情況下建立後續批次。

13. 身為角色專案使用者，我想分別保存固定角色特徵與每張貼圖的變化，讓臉部特徵與角色身分保持穩定，同時能改變表情。

15. 身為角色專案使用者，我想為個別貼圖指定服裝或道具變化，讓同一角色可穿雨衣、撐雨傘或配合節慶主題。
16. 身為角色專案使用者，我想在套用服裝變化時保留固定角色特徵，讓服裝提示詞不會把角色變成另一個人。
17. 身為角色專案使用者，我想使用嚴格參考修正角色明顯漂移的結果，讓工具重新使用角色檔中的五張角度參考圖，而不必手動上傳。
18. 身為角色專案使用者，我想讓一般產生僅使用角色定稿圖，而非每次都使用五張原圖，讓後續批次更快且降低圖片輸入成本。

22. 身為貼圖創作者，我不想看到虛假的 seed 設定，讓我不會誤以為 OpenAI 圖片 API 能保證確定性輸出。
23. 身為貼圖創作者，我想讓 AI 依選定的視覺風格繪製貼圖文字，讓文字看起來是貼圖插畫的一部分。
24. 身為貼圖創作者，我想選擇手寫、可愛圓體、粗筆或漫畫標題等 AI 文字風格，讓文字風格符合貼圖情緒。
25. 身為貼圖創作者，我想將貼圖文字輸入為多個段落，讓我能明確分開「辛苦了」與「你最棒」等詞句。
26. 身為貼圖創作者，我想讓 AI 決定分段文字位於上下、左右或不同對話框，讓文字能配合每張貼圖的姿勢與留白。
27. 身為貼圖創作者，我想讓 AI 保留輸入的文字段落及順序，讓自動構圖不會遺漏我想傳達的訊息結構。
28. 身為貼圖創作者，我想使用不產生文字模式，讓我能在匯出貼圖後於其他工具自行加字。
29. 身為貼圖創作者，我想讓不產生文字模式要求 AI 不繪製任何中文字元、數字、標題或其他文字，讓後續文字編輯可從乾淨圖片開始。
30. 身為貼圖創作者，我想看到 AI 繪製文字屬於插畫產生而非確定性排版的提示，讓我在上架 LINE 前檢查文字是否正確且清楚。
31. 身為貼圖創作者，我想保留產生貼圖包、`main.png` 與 `tab.png` 的流程，讓此功能不會影響 LINE 匯出支援。
32. 身為角色專案使用者，我想在改變角色身分基準後看到定稿確認立即失效，讓過期角色定稿圖不會被拿去產生新貼圖。
33. 身為角色專案使用者，我想讓損毀、過大、格式不符或版本不支援的角色檔在匯入前被完整拒絕，讓目前專案不會被部分覆蓋。
34. 身為批次貼上使用者，我想用字面值 `\n` 表示文字分段，讓一行一張貼圖的批次格式仍能支援兩個文字段落。
35. 身為不產生文字模式的使用者，我想只輸入動作說明，讓我不必填寫不會送給 AI 的貼圖文字。
36. 身為貼圖創作者，我想只對失真的單張貼圖啟用嚴格參考，讓其他貼圖不必負擔額外圖片輸入成本。
37. 身為付費 API 使用者，我想讓圖片產生失敗後只能手動重試，讓工具不會因自動重試而造成重複產生與重複計費。
38. 身為重視隱私的使用者，我想在上傳前知道參考圖會經過本站代理並傳給所選 AI 供應商，讓我能理解資料傳遞範圍。
39. 身為角色檔使用者，我想在保存的供應商或模型無法使用時看到明確提示並自行選擇替代模型，讓工具不會靜默改變產生設定。

## 實作決策

- AI 貼圖生成工具提供兩個頂層模式。單次貼圖是預設快速流程，不建立角色檔。角色專案是可重用角色流程，必須先通過角色定稿確認。
- 單次貼圖接受一至五張帶有角度標記的參考圖。第一張主要參考圖必填，其餘角度選填。工具在該批每次圖片產生請求都附上所選參考圖，瀏覽器工作階段結束後不保留這些資料。
- 角色專案要求五張明確標記的參考圖：正面、上方視角、下方視角、左側、右側。使用者確認角色定稿圖前，不可開始產生貼圖。
- 角色定稿狀態包含「尚未建立」、「產生中」、「等待確認」、「已確認」與「確認已失效」。更換原始參考圖、固定角色特徵、固定配件或插畫風格時，狀態必須轉為「確認已失效」；匯入通過完整驗證的角色檔可直接還原為「已確認」。
- 角色描述將固定特徵與可變屬性分開。固定特徵包含身分辨識外觀、身形比例、固定配件與插畫風格。可變屬性包含預設服裝、暫時配件、道具、動作、表情與個別貼圖情境。
- 角色檔採 `.hd-character.zip` 封存格式，包含 `manifest.json`、`character.png`，以及 `references/front.png`、`references/top.png`、`references/bottom.png`、`references/left.png`、`references/right.png`。`manifest.json` 至少記錄 `schema_version`、供應商、模型 ID、提示詞版本、插畫風格、固定角色特徵、固定配件、預設服裝與各圖片用途。
- 角色檔絕不包含 API key、已產生貼圖結果或與角色無關的瀏覽器設定。圖片在封存前統一轉成 PNG，最長邊不超過 1024px。
- 匯入角色檔時，先在暫存狀態完成整包驗證，再一次取代目前專案。只接受白名單檔名；`manifest.json` 不超過 256KB；封存檔不超過 40MB；解壓後總大小不超過 50MB；檔案數量不得超過七個；所有圖片必須實際解碼成功。任何一項失敗都不得部分套用。
- 匯入器只接受明確支援的 `schema_version`。遇到較新的未知版本、缺少供應商或模型、保存模型已無法使用時，不可靜默降級；必須顯示原因，並由使用者選擇目前可用模型後再繼續。
- 匯入角色檔只在瀏覽器本機還原角色專案。本站代理與伺服器不得持久化角色圖片、角色描述、API key 或產生結果。介面必須告知使用者，產生時參考圖與提示詞仍會經本站代理傳給所選 AI 供應商。
- 一般角色專案產生只將已確認角色定稿圖與角色描述作為參考基準。嚴格參考只出現在單張「重生這張」流程，並額外附上角色檔中的五張原始參考圖，共六張參考圖。初版不提供整批嚴格參考。
- 前端對所有參考圖重新編碼並縮至最長邊 1024px。後端仍必須獨立驗證最多六張圖片、允許的 PNG、JPEG、WebP 格式、實際可解碼內容、每張不超過 10MB、最長邊不超過 4096px，以及整個請求的總大小上限，不可信任前端驗證。
- 本站代理以重複的 multipart `reference` 欄位接受一至六張圖片。OpenAI 上游請求轉成多個 `image[]`；Google 上游請求轉成多個 `inline_data`。沒有參考圖時才使用純文字圖片產生端點。
- OpenAI 為初始供應商，`gpt-image-2` 為初始模型。Google 保留為可選替代供應商。匯入角色檔時還原保存的供應商與模型；若不可用，由使用者明確選擇替代設定。
- 不提供 seed 輸入欄位。工具所用的 OpenAI 圖片介面沒有確定性 seed 控制，一致性應透過參考素材、已確認角色定稿圖、固定特徵提示詞，以及保存的模型與提示詞中繼資料維持。
- 貼圖文字模式收斂為「讓 AI 畫文字」與「不產生文字」。既有本機 Canvas 疊字及保留專用文字區功能一律移除，不保留平行路徑。
- AI 繪製文字的文字風格是整批設定，可選手寫、可愛圓體、粗筆或漫畫標題。系統要求文字正確、清楚且不被裁切，但不宣稱插畫產生的文字絕對正確。
- 個別貼圖文字欄位支援一至兩個非空白段落。段落邊界代表語意分段，不是固定幾何換行：AI 必須保留段落文字與順序，但可自行決定上下、左右、對話框或其他合適構圖。初版不提供手動上下／左右版位選項。
- 「讓 AI 畫文字」模式的批次貼上維持每行 `文字|動作說明`，文字內以字面值 `\n` 表示第二段；解析後移除空白段落，超過兩段時整批拒絕套用。「不產生文字」模式改為每行只輸入動作說明。切換到不產生文字時，已輸入文字保留在瀏覽器狀態中但不送給 AI，切回後可恢復。
- 不產生文字模式明確要求 AI 省略所有形式的書寫內容，且不保留專用空白文字區。
- 圖片產生請求設定明確 timeout，但不自動重試。逾時、連線中斷或結果遺失後只能由使用者手動重新產生，介面必須提醒手動重試可能再次計費。失敗請求不得將角色定稿標示為成功。
- 既有背景去除、尺寸調整、透明度遮罩清理、ZIP 匯出、`main.png` 與 `tab.png` 產生流程維持不變，僅依新模式調整參考圖與提示詞輸入。

## 測試決策

- 驗證採兩個必要邊界，因為單一瀏覽器流程無法同時證明前端工作流程與後端多檔上游轉送契約。
- 第一個邊界是 FastAPI API 契約測試，沿用現有 `pytest` 與 `TestClient`。以 HTTP 測試替身取代 OpenAI 與 Google 上游，驗證一至六張參考圖、重複 multipart 欄位、OpenAI 多個 `image[]`、Google 多個 `inline_data`、純文字產生路徑、檔案數量與格式限制、timeout、錯誤轉換，以及 API key 不出現在錯誤訊息。
- 第二個邊界是實際瀏覽器驗收流程，使用可預期的本站 API 測試替身，不呼叫付費圖片服務。驗證單次貼圖、角色專案、五個具名角度欄位、角色定稿狀態與失效、角色檔匯出再匯入、一般參考、單張嚴格參考、文字分段、不產生文字，以及貼圖結果與 ZIP 匯出。
- 瀏覽器流程屬於完成功能前必跑的 smoke test。若實作計畫決定加入永久瀏覽器自動化，才新增 Playwright 等開發相依套件；本規格不為單一功能預先強制引入新的前端測試工具鏈。
- 角色檔測試涵蓋正確匯出與匯入、未知 `schema_version`、遺漏檔案、額外檔案、損毀圖片、封存與解壓大小限制，以及失敗匯入不會部分覆蓋目前專案。
- 角色定稿狀態測試涵蓋正常確認、產生失敗、更換參考圖、修改固定角色特徵、修改固定配件、修改插畫風格與匯入已確認角色檔。
- 文字測試涵蓋單一段落、兩個段落、批次貼上的字面值 `\n`、超過兩段、不產生文字模式、模式切換後保留文字，以及不同供應商共用「讓 AI 畫文字」語意。
- 好的測試只驗證使用者可觀察結果與 API 請求契約，不驗證原始碼片段順序、內部變數名稱、完整提示詞字串或模型像素結果。
- 既有 FastAPI 頁面測試保留在頁面可用性與穩定標記契約，不再以新增原始碼文字斷言作為主要互動測試。

## 範圍外事項

- 訓練、微調、LoRA、臉部嵌入儲存，或其他外部身分模型。
- 虛假的 seed 或供應商專用 seed 參數、像素完全相同的重複結果，或所有產生結果完全一致的保證。
- 伺服器端保存角色檔、參考圖片、產生圖片、API key、帳號或分享連結。
- 多人角色資料庫、雲端同步、權限角色、計費或協作功能。
- 自動臉部辨識評分、相似度評分，或不經使用者確認便自動選出最佳角色定稿圖。
- 本機後製文字排版引擎、字型選擇、顏色選擇、陰影控制、確定性的手動文字版面，或強制上下／左右文字位置選項。
- 不產生文字模式中的專用空白文字框或保留可編輯文字區。
- 除新參考圖與提示詞輸入外，改動 LINE 貼圖尺寸、背景去除策略、透明度遮罩清理或 ZIP 命名。
- 移除 Google 作為可選供應商，或新增既有 OpenAI 與 Google 以外的供應商。

## 補充說明

- OpenAI 官方文件確認圖片編輯端點可接受一張以上的參考圖。`gpt-image-2` 對每張參考圖自動採用高保真處理，可能提高圖片輸入成本，因此一般流程只送角色定稿圖，嚴格參考才附加五張原圖。參考： https://developers.openai.com/api/docs/guides/image-generation 。
- 使用目前的 `gpt-image-2` 別名符合預設使用最新模型的需求。角色檔同時記錄供應商與選定模型，讓創作者在模型別名日後更新時仍可辨識原設定。
- AI 產生繁體中文文字是已確認的產品決策。工具仍應要求精確文字與清楚可讀性，使用者在上架前仍有責任檢查文字。
- 本規格採用現有工具已建立的產品用語：AI 貼圖生成工具、參考圖、貼圖內容、角色定稿圖、角色檔、嚴格參考、單次貼圖、角色專案與不產生文字。
 
## Preflight Checklist（feature-specific）

> 開工前檢查一輪，完工後使用同一份清單再次檢查。

### 明確不做

- [ ] 不新增或修改資料庫 schema，不做 migration。
- [ ] 不新增帳號、雲端角色庫、分享連結或伺服器端持久化。
- [ ] 不新增 OpenAI 與 Google 以外的 AI 供應商。
- [ ] 不修改 LINE 貼圖尺寸、背景去除策略、透明度遮罩清理或既有 ZIP 命名。
- [ ] 不部署、不修改正式環境，也不順手重構其他工具。

### 角色狀態與業務規則

- [ ] 角色定稿確認只能由成功產生且經使用者確認的圖片進入。
- [ ] 原始參考圖、固定角色特徵、固定配件或插畫風格變更後，既有確認立即失效。
- [ ] 產生失敗、逾時或回應無圖片時，不得留下已確認狀態。
- [ ] 嚴格參考只套用於使用者明確選擇的單張重新產生。

### 圖片、角色檔與個資

- [ ] 前端與後端都驗證圖片數量、格式、大小與尺寸，後端不可信任前端結果。
- [ ] 角色檔匯入採白名單檔名、版本驗證、檔案數量、封存大小與解壓大小限制。
- [ ] 所有圖片都以實際解碼驗證，不只信任副檔名或 MIME type。
- [ ] 匯入先完整驗證至暫存狀態，失敗時不部分覆蓋目前專案。
- [ ] 角色檔不包含 API key，介面提示角色檔內含原始照片，應妥善保管。
- [ ] 介面告知使用者，產生時圖片與提示詞會經本站代理傳送給所選 AI 供應商。

### API key、代理與外部付費服務

- [ ] API key 只存在瀏覽器與單次請求記憶體，不寫入角色檔、伺服器儲存或日誌。
- [ ] 錯誤訊息、上游錯誤摘要與測試失敗輸出不得包含 API key 或完整請求內容。
- [ ] OpenAI 與 Google 請求都有明確 timeout。
- [ ] 付費圖片產生不自動重試；手動重試前提示可能再次計費。
- [ ] OpenAI 多個 `image[]` 與 Google 多個 `inline_data` 都有契約測試。
- [ ] 未加入使用者可控制 URL，不存在 SSRF 路徑。

### 相依套件與瀏覽器資源
