# TIF 轉 JPG 查核

採用 UTIF.js 3.1.0（MIT）在瀏覽器內解碼，再接現有 jSquash 壓縮流程。沿用動態載入，避免一般圖片也下載 TIFF 套件。選「原格式」時輸出 JPG，因本次需求是轉 JPG，未加入 TIFF 編碼。保留既有輸出格式選擇。

最初實作範圍不修改其他工具、不變更後端、不部署、不推送。後續使用者已另行授權正式部署及 Git 收尾，結果見 [部署紀錄](../../deployment-2026-10-05-tiff.md)。多頁、CMYK、超過 8 位元、需旋轉或鏡射的 TIFF 明確拒絕，避免漏頁、錯色或方向錯誤。透明區域合成白底；不保留印刷色彩描述檔及原始中繼資料。

- [x] MIME、副檔名及大小端檔頭辨識，不攔截既有 JPEG、AVIF、HEIC。
- [x] 解壓縮像素前檢查 50 MP 尺寸上限。
- [x] 無效、多頁與不支援的 TIFF 顯示錯誤，不靜默略過。
- [x] 套件版本固定，MIT 授權，讀取官方 API 文件。此工作階段沒有可用的 Context7 工具。
- [x] 瀏覽器實測未壓縮、LZW、Deflate、PackBits，下載 JPG 確認尺寸與色彩。
- [x] 資料庫、權限、時區、對外通知及使用者 URL 擷取不適用，此流程不新增後端 API。

驗證：`node --test tests/tiff_decode.test.js`。Playwright 從檔案選擇器加入四個 320 × 240 TIF，再按壓縮及下載；Pillow 讀回 JPG，尺寸 320 × 240，中心色彩（180, 80, 30）與來源相符。多頁、損毀檔案無下載結果，顯示錯誤。

補充實測：TIF 寬度縮至 160，下載 JPG 為 160 × 120；既有 PNG 成功壓縮；CMYK 與 64 MP TIFF 均顯示明確錯誤。
